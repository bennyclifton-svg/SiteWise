# Accounts: sign up and sign in with email and password

Date: 3 November 2026. Owner: Benny Clifton. Lane C (login).

## Outcome

Anyone with the link can create an account and start a project. They come
back with their email and password. Signing out no longer locks them out.

## Owner decisions (2026-11-03)

- Open sign-up. No access codes, no approval. Jev readings run at the
  owner's cost.
- One person, one account, many projects. No teammates, no invites, no
  sharing yet.
- A person belongs to one company only.
- Email provider not yet chosen. Recommendation: Resend (SMTP, free tier).

## Shape

- An account is the existing org with one user whose membership role is
  `owner`. Sign-up creates the org, user, membership and session in one
  transaction. Everything already scoped by `org_id` stays as it is.
- `users.password_hash` holds a bcrypt hash (cost 12). A partial unique
  index on `lower(email)` where a password is set makes the email a global
  sign-in name without touching older invite-only rows.
- Forgot password: one emailed link, single use, one hour. A reset ends every
  session of that user and signs them in.
- Invite tokens stay in the code because local dev login, the bench and the
  browser tests use them. The sign-in screen no longer asks for one.

## Routes (all under /api, origin checked)

| Route | Body | Result |
| --- | --- | --- |
| POST /signup | email, password | 204 + cookie; 409 email taken; 400 bad input |
| POST /signin | email, password | 204 + cookie; 401 "wrong email or password" |
| POST /password/forgot | email | 204 always (does not reveal accounts) |
| POST /password/reset | token, password | 204 + cookie; 401 expired or used |

Password: 8 to 72 bytes (bcrypt's limit). Email: trimmed, lower-cased,
must hold one `@`, at most 254 characters.

## Abuse limits

In-process limiter keyed by client IP (Caddy's X-Forwarded-For, trusted
only from loopback) and by email: 10 sign-in attempts per email per 15
minutes, 30 auth requests per IP per 15 minutes, 3 reset mails per email per
hour. Over the limit answers 429. A single binary makes in-memory counters
sufficient; a restart clears them.

Unknown email on sign-in still runs one bcrypt compare so timing does not
reveal which emails have accounts.

## Speed

New budget path `account_auth`: p50 ≤ 500 ms, p90 ≤ 1 000 ms. The bcrypt
hash dominates on purpose. No Jev call on any of these paths.

## Mail

`SITEWISE_SMTP_ADDR`, plus new `SITEWISE_SMTP_USER` and
`SITEWISE_SMTP_PASSWORD`. When a user is set, mail uses SMTP AUTH (PLAIN over
STARTTLS, standard library). Resend: `smtp.resend.com:587`, user `resend`,
password = API key, sending domain verified by DNS. Without SMTP in local dev
the reset link is printed to the server log, and only when `-dev-login` is on.

## Out of scope

Teammates, sharing, email verification, Google/Microsoft sign-in, changing
email, deleting an account, 2FA.

## Edge cases

- Same email signs up twice (any case): 409, "An account with that email
  already exists. Sign in instead."
- Reset requested for an unknown email: 204, nothing sent.
- Reset link used twice or after an hour: 401.
- Mail provider down: forgot still answers 204; the failure is logged
  without the token.
- Existing invite-only users (dev owner) have no password; they cannot sign
  in by password until an operator runs `sitewise set-password`.
- Someone signs up with another person's email: the real owner can take the
  account back with Forgot password. Accepted for now.
