Date: 7 October 2026. Lane A. Implements the original next-wave plan sections
4.5, D-12 and D-19; work-package contracts WP-24 and WP-27. No new dependency.

## Work subdivision

`POST /api/projects/{id}/works/{wi}/split` takes a version and 2–100 children.
It atomically converts the existing item to a group and creates editable children
with inherited action, system, part, target and evidence lineage. Child quantities
start unset: blindly copying the parent's total would double-count it. Children
are accepted for planning, never automatically verified. Nested splitting works.
Responsibilities and costs remain on their original parent. Existing package
inheritance and costing read that hierarchy.

`POST .../retire` checks the optimistic version and refuses with 409 plus typed
blockers while live responsibilities, open delivery records, draft posting cost
values or live children reference the item. Retirement keeps history and makes
the row user-owned so rebuilds cannot revive it. Split/retire use the existing
project write lock, revision, rebuild and event transaction.

The existing PATCH also supports system and part changes. It validates site/org
ownership, preserves stable identity and protects corrected coarse scope from
subsequent evidence generation. The scope picker resolves moved IDs by their
current semantic scope, updates only matching system/part descendants, and
refuses reset while children remain. Same-system children produce one scope
summary, with a visible note when individual inclusions differ.

Tests added cover atomic rollback on a foreign part, wrong org, stale versions,
nested splitting, parent blockers, retirement across rebuild, moved identities,
scope toggles, mixed scope and the API contract. Existing work correction and API
tests pass with the new behavior.

## Signals

Signals join the existing background evidence fan-out. Catalogue `runs_on`
matches only the passage's existing labels, including ancestor matching; it does
not speculate additional signal leaves or send a second request. Existing
presence/action speculative questions are unchanged. Unlabelled signals remain
unknown until evidence is labelled appropriately.

Noul answers are stored as `sig.<id>` facts with passage provenance and a
`noul_probability` basis. A conservative provisional selected-answer probability
of 0.9 is required; this is not Jev choice confidence and is not a calibrated
per-signal accuracy claim. Ambiguity remains unknown. Conflicting true/false
readings retain both citations and remain unknown. A supported true signal marks
the relevant proposal `addressed_by_evidence`; it stays visible and is never
automatically dismissed. Accepted/dismissed user decisions retain precedence;
changed semantic fingerprints reopen previous dismissals.

TypeSafe pages read for this implementation:
[fan-out](https://docs.typesafe.ai/patterns/fan-out),
[confidence](https://docs.typesafe.ai/confidence),
[API](https://docs.typesafe.ai/api), and
[Jev 1.13 limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13).

Pure profile, works and knowledge tests pass. Targeted jobs signal tests pass,
including matching/unrelated systems, ancestor matching, probability handling,
conflicting citations, missing evidence and decision precedence. HTTP and store
tests for work subdivision and existing corrections pass against local PostgreSQL.
