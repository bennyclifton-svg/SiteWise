# Next-wave local restore verification — 7 October 2026

The operator `restore-check` now captures all public tenant tables, not only
intake counts. Each table/organisation has a stable row count and SHA-256 over
ordered JSONB rows in a UTC repeatable-read transaction. Output contains hashes,
counts and identifiers, never row text. Old source reports without these digests
are rejected during comparison, requiring a new source baseline.

Issued reports additionally require a canonical snapshot hash matching the
saved report/version identity and a file record for the export in the same org.
Existing operator blob verification checks the referenced bytes. A same-count
cost edit changes the digest and is detected.
