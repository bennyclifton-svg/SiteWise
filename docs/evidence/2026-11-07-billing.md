# Billing, limits, email confirmation, team invites and legal pages: evidence

Branch `billing/v1`. Design `docs/design/2026-11-07-billing.md`, plan
`docs/plans/2026-11-07-billing-implementation.md`. Lane C. No Jev calls on
any new path; no new dependency (Stripe over HTTPS, hand-written).

## What calls what

- **Account page** `GET /api/account` → three indexed reads (profile, org
  billing, usage). No Stripe call.
- **Upgrade** `POST /api/billing/checkout` (owner only) → one Stripe call to
  create a Checkout session → browser goes to Stripe. The org id travels in
  Stripe metadata set by the server, never from the browser.
- **Manage billing** `POST /api/billing/portal` (owner only) → one Stripe
  call → browser goes to Stripe's Customer Portal.
- **Stripe → SiteWise** `POST /api/stripe/webhook` → signature check
  (HMAC-SHA256, five-minute window) → event recorded once by id → org plan,
  status, period end written in one transaction; events older than the last
  applied one are ignored.
- **Limits**, only when billing is configured (production requires it):
  every upload path (documents, fee proposals, program files, invoices)
  checks confirmed email, monthly documents and storage before reading the
  body; project create checks the project cap; invites check seats. Each new
  document adds one to `org_usage` (counted even with billing off, to
  measure real use).
- **Email confirmation**: sign-up requires accepting the terms (version
  stored), mails a 24-hour link `/#verify=…`; `POST /api/email/verify`.
- **Team**: owner invites (`/#invite=…`, 7 days); invitee sets a password and
  joins the owner's org as member; owner can cancel invites and remove
  members (sessions end, password cleared, records kept).

## What could fail

- Stripe down: Upgrade and Manage billing show "try again"; nothing else is
  affected, limits keep working from the stored plan.
- Webhook not delivered: Stripe retries for up to three days; the plan
  updates when it lands. A store error answers 500 so Stripe retries.
- Webhook secret wrong: every event is refused with 400 and logged
  ("signature rejected"); plans stop updating. Section 8 step 9 catches it.
- Parallel uploads at the cap may each pass (overshoot at most the number in
  flight). Accepted in the plan.
- An unknown Stripe price (for example a price created later and not
  configured) keeps the org's plan unchanged and logs the price id.
