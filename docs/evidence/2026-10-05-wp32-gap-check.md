# WP-32 gap check

Lane A. Outcome: expose missing or overlapping accountable package roles for
accepted work, reducing boundary decisions without appointing anyone. No
writes, Jev, scheduling or new UI. Budget p50 50 ms / p90 150 ms.

Implemented `GET /api/projects/{id}/gaps`, scoped to the member's organisation.
The store reads works, packages and scope in one repeatable-read transaction;
the pure checker returns stable item/role findings with contributing package
and scope IDs. Proposed items are `not_yet_accepted`; excluded, retired and
group parent items are not checked as individual work.

Physical actions need one works installer; multiple suppliers overlap, while
an owner supply package never substitutes for an installer. Actions now have
the required explicit `needs_design` boolean in the draft action catalogue,
schema, Go loader and Python checker. New, replace, upgrade, alter and repair
need one designer: services or explicitly assigned works (D-33). Investigation
counts distinct packages holding inspect/test; retained systems need at least
one works package holding maintain-operation/protect, without overlap findings.
Nearest-parent responsibility inheritance applies separately per role; a
child's role replaces the inherited role. Split mutation integration remains
part of WP-24.

Tests cover owner-PM and D&C allocation, missing/duplicate designers, ineligible
supply packages, removal, investigation, retained systems, group inheritance,
proposed/excluded/retired items, JSON assignment clearing a gap and tenant
isolation. Relevant knowledge, procurement, store, HTTP, latency and benchmark
suites passed (`.tools/wp32-tests.log`). All 30 Python tool tests passed. Strict
knowledge checking passed with zero errors and three existing unmapped legacy
complexity warnings. Missing/null/string `needs_design` is rejected explicitly.

Local benchmark: `bench/results/2026-10-05-wp32-gap-diagnostic.json`, 40 gap reads
over a growing project of 1–40 work items, p50/p90 **1.4/2.0 ms**, within 50/150.
All user-path gates passed; filing 443.7/594.5 ms within 1000/2000. This reduced
20-file-per-round, two-round development diagnostic uses recorded Jev latency;
it is not release/VPS evidence. Existing component budgets are reported and
judged on the target VPS under D-37. Large assigned/group workload timing and
actual split workflow integration remain to validate. No new dependencies.

Next dependency work: WP-35 minimal delivery, then the M1 report path; proposal
decision timing and remaining WP-31 reference tests also remain open.
