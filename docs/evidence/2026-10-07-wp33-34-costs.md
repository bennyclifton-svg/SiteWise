## Implementation

`internal/costs` uses decimal strings and `math/big.Rat`; half-away-from-zero rounds at the posting line. The API accepts decimal strings or plain decimal JSON numbers without going through binary floating point. Amounts persist as numeric(18,2), rates numeric(18,4). Totals sum exact rounded lines in Go; this retains the plan's numeric accuracy without a floating conversion or another database aggregate round trip. Group and excluded items do not post. Empty/missing metrics stay unavailable; partial values retain known subtotals and bounds. Forecast selects commitment, then estimate, then budget per posting line and records the basis; variance is unavailable unless budget and forecast are complete amounts.

Store transactions lock the project, validate actor and targets, use optimistic plan versions and bump the shared costs revision/SSE event. Value writes additionally check the metric version. All writes to an existing plan require its version ID to keep a stale browser from targeting a replacement draft. A works line assigned to a package requires that package's live work responsibility. Fees require a live package stage. Scope links contain IDs only, no duplicated money.

Baseline captures system/part dimensions, freezes values, revisions and links with SQL triggers, then clones a new editable draft preserving cost identities. Subdivision removes parent values, makes it nonposting and writes all children plus explicit residuals in one transaction, or deliberately permits a changed total. Unpriced allocations stay unknown. Removal affects only a draft occurrence, leaving frozen versions and stable identity untouched.

Quantity/rate calculation is explicit (`calculate: true` on a budget/estimate value write); it records method version, inputs, actor and limitations and labels the result `calculation`. Claimed-to-date requires a date. No reviewed benchmark records were supplied or promoted; amounts remain user-entered or explicitly calculated from user inputs.

Migration 021 defines the schema. The initial version was applied by another agent's test process while implementation continued; its applied text was retained. Additive 021a defers composite constraints for tenant cascade order; 021b adds tenant cascade ownership and permits immutable-record deletion only as part of deleting its owning tenant. Ordinary frozen writes remain rejected.
