# Unit mix: evidence

Plan: `docs/plans/2026-11-08-unit-mix.md`. Built 8 Nov 2026.

## What changed

- `knowledge/profile/taxonomy.yaml`: five scale fields (`units_studio`,
  `units_1_bed`, `units_2_bed`, `units_3_bed`, `units_4_bed`) on apartments,
  BTR, townhouses, social and affordable housing, and the four mixed-use
  classes with homes. BTR's free-text `unit_mix` field is removed; the counts
  replace it. Scale fields may carry `asks` (SCHEMA.md).
- `internal/profile/unit_mix.go`: candidates are only counts written against
  a type phrase. `harvest.go` routes the five keys there; `questions.go`
  uses `asks` in the existing label fan-out question.
- `internal/knowledge/unit_mix.go`: `UnitMixText` prints known counts only.
- `internal/httpapi/profile.go` `listedScale`: a type known to have no mix
  does not list one from documents; where the mix is listed, Bedrooms is not
  listed from documents. User values always show.
- RFP project grid: a `Unit mix` row (`internal/knowledge/rfp.go`,
  `internal/rfp/drivers.go`, `resolve.go`), printed only when a count is known.
- Web: the card lists the mix after GFA; known counts show with the card
  closed, empty ones fold into "not yet known". The summary sentence adds
  "with 14 one-bed and 38 two-bed units".

What calls what: no new Jev call. The five questions join the label fan-out
a passage already makes when a type phrase with a count appears in it.

## Live Jev (jev-1.13.0, 8 Nov 2026)

`go run ./cmd/profile-eval -live` on six scratch cases (brief sentence,
schedule table, shop-top key information, word numbers, a house, a past
project in an experience list):

- Captured readings correct 9/9, all applied automatically (confidence ≥ 0.6).
- House ("4 bedroom home"): no mix question asked; nothing applied.
- Label call latency p50 223 ms, p90 273 ms.
- One forbidden reading: a past project in an experience list ("Harbour
  View, 120 apartments with 40 x 1 bed and 80 x 2 bed") was read as this
  project's mix at confidence 1. The existing `units` and
  `residential_units` questions read "120" from the same passage at
  confidence 1, so this is the standing limit of a one-passage reading
  (https://docs.typesafe.ai/model-jaggedness/jev-1.13), not new to the mix.
  Fixing it belongs with the other scale fields (for example skipping
  experience sections in tender returns), not in this change.
