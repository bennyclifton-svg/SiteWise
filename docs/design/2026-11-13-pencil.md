# Pencil: words from Haiku, figures from SiteWise

Date: 13 November 2026. Status: a proposal for owner review. Nothing in the
product is built. It changes binding rule 1 ("Jev only"), so no code lands
until the owner decides section 12.

Mockup (private, sample project): https://claude.ai/artifact/DeivcxA5FCSgmJK3rAVCsH
Source: `docs/design/mockups/2026-11-13-pencil/pencil.html`.

Read first: `AGENTS.md` (non-negotiables), `PRODUCT.md`,
`docs/design/2026-09-29-foundation-design.md` (sections 1, 4 and 6),
`docs/design/2026-11-12-project-report.md` (rule 2, "no machine-written
narrative"), `docs/design/2026-11-10-run-time-feedback.md` (ink motions).

## 1. Outcome

A project manager types a question in the band and the figures that answer it
are on screen before any model starts. Under a second later a few plain
sentences explain them. From a flag on the price table, or a failed invoice
check, one click drafts the letter the flag calls for. On opening a project
they read a short "since you last looked" that was written in the background.

Every figure in those words is SiteWise's own figure, with its origin mark and
its source one click away. The model writes the words between the figures.
It cannot change a figure. A figure it types for itself is highlighted until
the PM keeps or edits it.

Why it earns its place:

- **Time to decision.** Tender clarifications, invoice queries and catch-ups
  are the writing a PM does many times a week. Each is now a click and a read.
- **Market appeal.** Buyers now expect to ask their software a question and
  get a draft back. SiteWise has neither. The pitch: an assistant that answers
  in under a second and cannot make up a number.
- **Answer trust.** It holds because of the guard (section 5.3). Without the
  guard, Pencil would cost SiteWise the trust that is its edge.

Lane: A for the guard and the fact sheet (they restate cost figures, awards
and dates), B for the surfaces, C for the new dependency and the data that
leaves the server.

## 2. The critical question: where an LLM fits in this product

SiteWise's edge is speed and trust: a filing in a second, and a figure you can
rely on. An LLM threatens both. Generation is slow next to Jev's picks. A
model that can type a number can type a wrong one, and a chat agent that loops
through tools adds a full model call per round. The common way to add AI to a
product (a chat panel with tools, or a model reading documents into fields)
would make SiteWise slower and less trustworthy, the two things it sells on.

SiteWise does lack language. The foundation chose "Jev picks the content and
approved template wording writes it" (foundation section 4). That works for
fixed sentences, but it cannot answer a question it has not seen or draft a
letter that fits the flags in front of it. That is the gap, and it is narrow:
**words around figures SiteWise already holds.**

So the division of labour is:

| Who | Does | Unchanged? |
|---|---|---|
| Jev | Files documents; reads profile evidence, invoices, proposals, program files | Yes. Still the only AI that judges. |
| Go | Money, dates, counts, ranges, rule lookups, and now one fact sheet per project | Yes, plus the fact sheet |
| Haiku | Writes answers, letters and catch-ups from the fact sheet; may write a figure only as a fact's tag | New |

## 3. What Haiku never does

- Files a document, reads a document into a field, or replaces any Jev question.
- Writes to a cost line, package, award, program date, specification value,
  profile value or document record. Pencil's only writes are its own drafts.
- Runs while someone types or navigates. Every call follows an explicit click
  or Enter, or is background work.
- Produces a figure, date, duration, count, rule number, price, rate, firm
  name or person's name. Those come from the fact sheet only (5.3).
- Calls tools or loops. One request, one streamed response.
- Sends anything. A draft is copied or inked by the PM. Nothing goes out by
  itself.

## 4. Approaches considered

| Approach | Wait | Can invent figures | Verdict |
|---|---|---|---|
| A. Chat agent with tool calls over the API | One full model call per tool round; usually several | Yes | Rejected. Serial round trips break the speed rule ("one fan-out per state, never serial round trips"). It also gives the model write paths. |
| B. Haiku reads documents in place of Jev | Adds generation to filing | Yes | Rejected. Filing keeps its 1 s budget and its answer keys. Generative extraction invents values that pre-parsed extraction cannot. |
| C. Template wording only (the foundation's plan) | None | No | Kept as the fallback whenever Pencil is off, down or slow. |
| D. **Pencil**: one streamed call over a stored, cached fact sheet; words only; figures pinned | First words targeted under 1 s | No. Typed figures are caught. | Proposed. |

A later step, not in this proposal: answers from inside documents. Search
already plans a Postgres shortlist judged by Jev (foundation section 4). If
Jev picks the passages and Haiku words the answer with each passage cited, the
same division of labour holds.

## 5. Design

### 5.1 The fact sheet (Go, background)

One text block per project, rebuilt in the existing worker whenever a record
it draws on changes. The rebuild is debounced, keyed by a hash of the project's
state and stored with that hash. Each line is one fact:

```
[f:cost.main.budget] Main works budget: $2,640,000 (set by you; Cost Plan › Construction › Main works, 3 Nov)
[f:tender.northline.total] Northline tender, ex GST (excludes rock excavation): $2,598,000 (computed; price table)
[f:prog.pc.late] Practical completion, latest: 13 Dec 2027 (computed; authority connection durations unknown)
```

- Values come from the same Go rollups the screens use. One figure, one owner.
- Derived figures a sentence might need (differences, ranges, "with the
  missing item added at the lowest and highest tendered price", days to a
  date) are computed here, so Haiku never needs to do arithmetic.
- Unknown is a value. An unpriced line is in the sheet as "unknown".
- Each fact carries its origin (documents, typical, user, computed, to check)
  so the chip shows the profile's origin colours.
- Order is stable (building order, then surface order) and the text is
  deterministic, so the prompt prefix caches.
- Rule numbers enter only from `knowledge/` with their `verified` flag. An
  unverified one renders with its amber "unverified" mark wherever it appears.
- Scoped by `org_id` and project like every read. One project per request.
- Size target: 8,000 to 20,000 tokens. It must stay above the model's minimum
  cacheable prefix or it won't cache. Small projects simply won't cache, and
  at Haiku prices that is acceptable.

### 5.2 One call per state, streamed

Request shape (Anthropic Messages API, Go SDK):

- `model: claude-haiku-5-5`.
- `output_config.effort: low`, and thinking disabled, which Haiku 5.5 accepts at
  effort high or below. That gives the fastest first token; the job is
  constrained writing, not reasoning.
- System prompt: the fixed rules, cached. Then the fact sheet, with a
  `cache_control` breakpoint. Then the question or task, the only part that
  changes per call.
- No tools. No `temperature` (rejected from API version 2026-10-21). No
  assistant prefill (rejected on current models). Plain text out.
- `max_tokens` sized per surface: about 400 for Ask, 700 for a letter.
- Streamed to the browser through a Go handler as server-sent events. Go sends
  the facts first, then text deltas, then the final check (5.3).
- Interactive calls have no retries. If no first token arrives within 2.5 s,
  the call is dropped: the facts stay on screen and a letter falls back to
  template wording. The whole call is capped at 10 s.
- A circuit breaker and a kill switch (server config, plus an org setting)
  work like the Jev client's. Every call's latency, tokens, cache reads and
  stop reason are logged.
- `stop_reason: refusal`: Haiku 5.5 has no server-side fallback, so show the
  facts and say no draft was written.
- Pre-warm: when an open project's fact sheet changes, a background request
  with `max_tokens: 0` writes the cache, so the next question reads it.
  Measure whether the 5-minute or the 1-hour cache pays for itself.

Why Haiku and not a larger model: the job is short, constrained writing over
supplied facts. Speed and cost matter more than depth. If a measured surface
needs more, that surface changes model, and the guard stays the same.

### 5.3 Figures are pinned (the guard)

1. The prompt allows a figure only as its tag, `{f:id}`. Haiku is never asked
   to add, subtract, compare or convert. Every result it may need is already
   in the sheet.
2. Go replaces each tag with the fact's value and origin. A tag that names no
   fact is an error, shown in red. That draft cannot be inked; discard it and
   draft again.
3. Go then scans the remaining text for digits, currency, percentages, dates,
   clause-like tokens and cardinal number words ("two" to "billion"). Each
   one is highlighted with the squared highlighter, the existing "needs a
   decision" mark: "typed by Haiku, check it". The PM keeps it as their own
   word (it turns rust, the user origin) or edits it.
4. A draft cannot be inked until every typed figure is kept or edited (owner
   decision 6). Inking writes the PM's text, with a record of which words were
   Haiku's and which figures came from which facts.

The browser runs the same scan while text streams in, for display. The
server's scan on the final text is the authority, and it is saved with the
draft.

The mockup runs this guard on its sample texts and on live Haiku output. On
its seven sample texts (four answers, two letters, one catch-up) it finds no
tag without a fact, and exactly one typed figure ("3 business days"), placed in the clarification letter on purpose.

### 5.4 Surfaces

| Surface | Where | Trigger | Model call |
|---|---|---|---|
| Ask | A field in the butter-paper band, Ctrl/Cmd K | Enter or a suggested question | One, streamed. Facts come first from a code lookup on the stored fact sheet (names, synonyms, Postgres full-text). |
| Draft | Beside a flag: price-table flags (clarification to tenderers), failed invoice checks (query to the supplier). Later: program slips, RFP issue cover notes, regret letters. | A click | One, streamed |
| Catch-up | Top of the Profile on open; later the Report's draft summary | Background, after state changes settle | One per settled state, stored; opening costs a read |

Ask answers questions about the workbench's records. A question about what a
document says gets an honest "SiteWise doesn't hold that" plus the document
link, until the Search step in section 4.

### 5.5 How it looks (Trace)

- Pencilled words are graphite: lighter than ink, with contrast still at AA.
  "Ink it" turns them to ink with the existing `ink-write` wipe. The metaphor
  is the office's own: a draft is pencil until someone inks it.
- Figures are chips: mono, tabular, with the origin dot (green documents, rust
  yours, ring computed, blue typical, amber to check). A click shows the
  label, the value, how it was decided, the source, and "Show in the price
  table".
- Figures Haiku typed carry the squared highlighter until kept (rust underline)
  or edited.
- A quiet "Pencilled by Haiku" rule sits above the words. No sparkles and no
  "AI" badge (PRODUCT voice: no AI theatre).
- "Show what Haiku wrote" reveals the tagged text, for anyone who wants to see
  how the guard works.

### 5.6 Failure handling

| Failure | What the user sees |
|---|---|
| Anthropic down, slow (no first token in 2.5 s), or breaker open | The facts stay. Ask shows "No words this time; the figures above are SiteWise's own." A draft shows template wording. Nothing else on the page changes. |
| Refusal | Facts only, and "No draft was written." |
| A tag that names no fact | Red "no such figure"; the draft cannot be inked |
| A typed figure | Highlighted; blocks inking until kept or edited |
| Rate limit | "Pencil is busy, try again in a minute." No automatic retry while someone waits. |
| Catch-up job fails | The previous catch-up stays, marked with its date. The worker retries with backoff. |

### 5.7 Isolation, data and prompt injection

- What leaves the server is the project's fact sheet (records and figures,
  not documents) plus the question. Owner decision 2 covers the org switch and
  where processing happens. Confirm Anthropic's current commercial and
  retention terms before launch, and whether an Australian processing option
  is needed.
- The fact sheet is built per org and project. No request carries another
  project.
- Some record text came from documents (exclusion wording, titles), so
  injected instructions are possible. The model has no tools and no write
  path, its figures are pinned, and the PM reads every draft before it goes
  anywhere. The worst case is an odd paragraph the PM discards.
- `internal/pencil` (the proposed package) is imported by no filing, cost,
  procurement, specification or program package. A test of the import graph
  (`go list -deps`) fails the build if one does.

## 6. Speed budgets (proposed)

New rows in `bench/budgets.json`. The Haiku timings are targets until they
are measured from the Singapore server; there was no Anthropic key on the
development machine to measure them.

| Path | p50 | p90 | Note |
|---|---|---|---|
| `pencil_ask_facts` | 50 ms | 150 ms | Code only: stored fact sheet lookup |
| `pencil_first_words` | 700 ms | 1,500 ms | Ask or draft, click to first streamed word, cache warm |
| `pencil_ask_complete` | 2.5 s | 5 s | About 400 output tokens |
| `pencil_draft_complete` | 4 s | 8 s | About 700 output tokens |
| `pencil_catchup_open` | +5 ms | +10 ms | Added to the profile read; stored text |
| `pencil_fact_sheet_build` | 100 ms | 300 ms | Background, release build |
| Every existing path | unchanged | unchanged | Enforced by the existing benches and the import test |

Measure from the live server: 20+ samples per path, cache cold and warm,
and the cost of the 2.5 s first-token deadline (how often it fires).

## 7. Cost

Haiku 5.5 lists at $0.10 per million input tokens and $0.50 per million
output. These figures assume the usual cache prices: reads at a tenth of
input, 5-minute writes at one and a quarter times input.

| Use | Tokens | Cost |
|---|---|---|
| Ask | 12k cached in, 200 new in, 400 out | about $0.0003 |
| Draft | 12k cached in, 200 new in, 600 out | about $0.0004 |
| Catch-up after a change | 12k written to cache, 200 out | about $0.0016 |
| A heavy PM day: 50 asks, 10 letters, 20 catch-ups | | about $0.05 |

That is about a dollar a month for a heavy user, against the $50 and $200
plans. Owner decision 4 covers whether Free gets a monthly allowance.

## 8. Testing

- **Guard unit tests (Go):** tags resolve; an unknown tag is an error; digits,
  money, percentages, dates, clause-like tokens and number words are caught;
  words like "tender" and "often" are not.
- **Answer key:** about 40 questions across three fixture projects. Each has
  the facts the answer must cite, and a few that must get "SiteWise doesn't
  hold that". The scorer counts unpinned figures (must be 0 after the guard
  marks them), cited facts, and honest refusals. Run it live, as the Jev
  answer keys are.
- **Letters:** each draft kind against fixture flags. Every flag addressed,
  addressed to the right firm, no figure without a tag.
- **Import graph:** filing and the other core packages never depend on
  `internal/pencil`.
- **Benches:** the rows in section 6, `where: release`, from the server.
- **Browser (Playwright):** the facts appear before the words; "Ink it" is
  blocked by a typed figure; Haiku down gives facts and template wording.

## 9. Rule changes proposed

AGENTS.md non-negotiable 1, replace with:

> **Jev judges; Haiku only writes words.** Jev (TypeSafe System One) is the
> only AI that judges: filing, reading and every pick. Pencil may call
> Claude Haiku to write answers, drafts and catch-ups from a fact sheet Go
> builds. It never files or reads documents into fields, never writes a
> project record, never produces a figure, date, rule number or firm name
> except as a fact's tag, never calls tools, and never runs while a user
> types or navigates. No other LLMs, embeddings or chat agents.

Foundation section 0, point 2, and PRODUCT.md "Positioning" change to match.
Report framework rule 2 ("No machine-written narrative") becomes: "Words may
be pencilled by Haiku from the report's own figures. They are the PM's only
when inked. Figures stay pinned."

## 10. Out of scope

Answers from inside documents (section 4, later). Any write the model
proposes, including "add a line for landscaping". Voice. Sending email from
SiteWise. Sharing. Other models or providers. Embeddings.

## 11. Build order

1. Fact sheet and guard in Go, with tests. No model is called, so this can
   land under the current rules.
2. Draft: the clarification letter from price-table flags, and the invoice
   query from failed checks. This is the most value per risk.
3. Ask in the band.
4. Catch-up, folded into the Report module once its section 12 decisions are
   made.

Each step reports timing against section 6 and states what calls what.
